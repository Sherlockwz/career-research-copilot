# 需求文档 · 求职科研助手 Chrome 插件

> 本文件记录项目的**初始设想、功能需求、以及开发前确认的所有关键决策**。
> 目的：让接手者不读代码也能明白「这个插件要做什么、为什么这么设计」。

## 一、项目背景与设想

一款面向**学生 / 求职者**的 Chrome 扩展，服务两大场景：

1. **实习 / 校招 / 春招秋招投递**
2. **科研套词**（联系教授、申请 RA / 研究生 / 博士）

核心痛点与设想：

- 反复填写高度相似的申请表单很繁琐 → 希望「个人信息录入一次，处处自动预填」。
- 面对岗位 JD 或教授研究方向时，难以判断自己的背景如何匹配、如何优化 → 希望有 AI 给出**匹配分析、优化建议、套词草稿**。
- 以「**个人结构化数据**」为中枢：一次录入，投递和套词都复用。

## 二、三大功能需求

### 功能 1：简历解析/ 个人数据录入
- 上传简历 **PDF**，插件读取并生成**结构化数据**。
- 也支持从**个人主页链接**读取信息并提取存储（由插件抓取网页正文，用户只需粘链接，不用手动复制正文）。
- 结构化数据可在插件内可视化编辑、增删改。

### 功能 2：自动预填
- 投递实习/校招时，根据结构化数据**自动预填**公司申请表单，方便用户后续微调。
- **自适应学习**：
  - 若表单出现插件当前存储中**没有的新信息**，或用户**做了调整**（改了之前填的内容、或在空字段补了信息），经**询问确认**后可补充/回写到存储。
  - 记住「某网站某字段 → 我数据里的哪一项」的映射，**越填越准**。
- 目标网站：主要是各企业自己的校招/实习官网，要填的信息比较相似；预填不准的地方交给用户调整，插件从调整中学习。

### 功能 3：页面扫描 +匹配 / 套词建议
停留在当前页面时，启用插件即可扫描当前页面内容，分两种场景：

**A. 投递实习 / 校招（岗位 JD 页）**
- 扫描岗位 JD，对现有资料给出调整/优化建议。
- 用户同意后，直接输出调整后的建议文案。
- 给**匹配建议**：如何更 match —— 从哪些方面入手、做什么事、补充哪些研究/项目以链接岗位。

**B. 申请 RA / 联系教授 / 申请研究生博士（教授主页）**
- 查看教授的研究方向及兴趣点。
- 基于现有资料做匹配，给建议：
  1. **如何套词**；
  2. 若要与该教授合作，基于现有内容/研究/经历，后续**如何展开、能如何合作**。
- 输出既要**要点建议**，也要**可直接发送的套词邮件草稿**。

## 三、开发前确认的关键决策

| 维度 | 决策 | 说明 |
|---|---|---|
| **AI 接入** | 用户自填 API Key | 插件不内置 Key；用户在设置里填自己的 Key |
| **支持厂商** | Claude / OpenAI / DeepSeek / Kimi / 自定义 | 后加了国内两家 + 自定义（中转站/自部署）。见开发历程第2轮 |
| **数据存储** | 仅本地 | 隐私优先，不上传服务器。IndexedDB 存 profile，chrome.storage 存设置/映射 |
| **PDF 解析** | 纯前端（pdf.js） | 浏览器本地提取文本，文件不离开电脑 |
| **主页读取** | 粘贴链接，插件抓取 | 用户只给链接，插件 fetch 网页正文再解析。见开发历程第 2 轮 |
| **语言场景** | 中英双语 | 简历、套词信支持中英 |
| **套词输出** | 要点 +邮件草稿都要 | |
| **前端技术栈** | Vite + React + TypeScript + Tailwind | 用 @crxjs/vite-plugin 打包 MV3 |
| **预填交互** | 直接填入 + 高亮 | 低置信字段特别标注（橙色虚线），用户逐个确认/修改 |
| **学习机制** | 字段映射学习 + 数据回写 | 记住站点字段映射；用户改动确认后回写个人库 |
| **首版范围** | 三大功能一起做到可用 | |

## 四、隐私原则（重要）

- 个人数据、简历原文只存在浏览器**本地**（IndexedDB + chrome.storage.local）。
- **API Key 只在 background service worker 读取**，不下发到注入网页的 content script。
- LLM 调用直接从插件发往用户选择的服务商，不经任何中转服务器。
